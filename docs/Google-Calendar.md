# Google Calendar

Двусторонняя синхронизация сайта с Google Календарём, где менеджеры ведут расписание.

- **Календарь → сайт.** События календаря закрывают время на сайте. Дата и время берутся из самого события, шоу-программа и персонажи распознаются в названии и описании. Распознанные персонажи и программы становятся занятыми в конструкторе (`/party-builder/`) и при финальной проверке заказа — с теми же буферами, что и заказы сайта (1 час до и после).
- **Сайт → календарь.** Когда заказ подтверждают (кнопка «✅ Подтвердить» в Telegram-боте или статус в админке), он появляется в календаре. Описание события — та же карточка заказа, что приходит в Telegram. Снятие подтверждения или отмена заказа удаляют событие.

Админка: `/admin/calendar` (пункт «Календарь» в меню).

## Настройка (один раз)

1. [console.cloud.google.com](https://console.cloud.google.com/) → создать проект.
2. APIs & Services → Library → включить **Google Calendar API**.
3. OAuth consent screen → тип **External**, название и почта → **Publish app** (статус «In production»). В статусе «Testing» Google отзывает доступ каждые 7 дней.
4. Credentials → Create credentials → **OAuth client ID** → тип **Web application** → в «Authorized redirect URIs» добавить адрес, который показан в админке (по умолчанию `https://animator-surpriz.uz/api/admin/google-calendar/callback`).
5. Client ID и Client Secret вставить в `/admin/calendar` (или задать `GOOGLE_OAUTH_CLIENT_ID` / `GOOGLE_OAUTH_CLIENT_SECRET` в `.env`).
6. «Подключить Google Календарь» → войти в аккаунт с календарём заказов → разрешить доступ. На экране «Приложение не проверено» — «Дополнительно → Перейти».
7. Выбрать календарь (по умолчанию выбирается основной) и при необходимости поменять настройки.

Запрашиваемые права: `calendar.calendarlist.readonly` (только список календарей) и `calendar.events` (чтение и запись событий).

Перед подключением на сервере должен быть ключ шифрования `GOOGLE_CALENDAR_TOKEN_KEY` в `.env` релиза (сгенерировать: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`), а в `surpriz-bot.service` — `Environment=GOOGLE_CALENDAR_WORKER=1`. Без ключа админка покажет, что подключение недоступно.

## Как распознаются события

`CalendarMatcher` в `core/google_calendar.py` ищет в тексте события фразы из каталога:

- полное название («Человек-паук №2», «Микки Маус (ростовой)»), название без уточнений в скобках и без «№N»;
- участники ансамбля («Леди Баг», «Супер-Кот» → «Леди Баг и Супер-Кот»; «Микки и Минни» → пара ведущих);
- название шоу без слова «шоу» («Серпантин» → «Серпантин-шоу»), slug и синонимы поиска каталога («Спайдермен», «Spiderman»);
- падежные окончания («Эльзу», «человека-паука»);
- свой словарь из админки («ЛБ» → «Леди Баг и Супер-Кот»).

Время: у обычных событий берётся из самого события. У событий «на весь день» — из текста, если оно там написано («15:00», «15:00–17:00», «с 12 до 14»; «05.10» считается датой, а не временем). Если времени в тексте нет, событие на весь день с распознанными персонажами закрывает весь день. Google по умолчанию помечает события на весь день как «свободен», поэтому для них это не учитывается — только отказ владельца.

Неоднозначности: совпадение с несколькими персонажами решается по контексту (второй участник ансамбля, номер «№2», слово «ростовой», длительность события для шоу «Игра в кальмара 60/90»). Общее упоминание «Человек-паук» занимает свободный костюм с учётом и заказов сайта (с тем же буфером ±1 час): если №1 уже продан на сайте, событие займёт №2; «2 паука» / «паук x2» займут оба.

Статусы событий в админке:

| Статус | Что значит | Закрывает время |
|---|---|---|
| Закрывает время | распознаны шоу и/или персонажи | да, только их |
| Не распознано | ничего не найдено | нет (или всё время, если включено «Нераспознанные события закрывают всё время») |
| Помечено «свободен» | в Google стоит «Показывать как: свободен» или владелец отклонил приглашение | нет |
| Не учитывается | админ нажал «Не учитывать» | нет |
| Заказ с сайта | событие создано сайтом, время совпадает с заказом | нет — заказ уже учтён в `party_orders` |
| Заказ перенесён в календаре | событие сайта сдвинули в Google | да — новое время закрыто, заказ на сайте не меняется |

Текст событий (он может содержать данные клиентов) хранится только для админки и не попадает в публичные API: конструктор видит лишь окна занятости и названия из каталога.

## Где что в коде

| Файл | Что делает |
|---|---|
| `core/google_calendar_store.py` | SQLite: настройки, импортированные события, очередь выгрузки, словарь, lease воркера. Без импортов других `core`-модулей. |
| `core/google_calendar.py` | OAuth, клиент Calendar API, распознавание, импорт, выгрузка заказов, фоновый воркер, данные для админки |
| `core/customer_store.py` | `_calendar_blocks_on`, `_calendar_closed_conflicts`, `_cast_free_conflicts`; блоки календаря в `check_character_availability`, `_check_program_conflict`, `get_busy_dates_summary`, `build_resource_availability_calendar`; постановка в очередь в `set_order_confirmation` и `apply_legacy_order_cancellation_by_public_id` |
| `core/admin_notifications.py` | воркер календаря стартует вместе с Telegram-воркером; после подтверждения в боте воркер будится сразу |
| `webapp/adapter/app.py` | раздел `calendar` (`/api/v2/admin/section/calendar`) и `/api/v2/admin/google-calendar/callback` |
| `webapp/src/app/api/admin/google-calendar/callback/route.ts` | OAuth redirect URI, возвращает на `/admin/calendar` |
| `webapp/src/features/admin/admin-calendar-section.tsx` | страница админки |

Таблицы: `google_calendar_settings`, `google_calendar_events`, `google_calendar_event_overrides`, `google_calendar_aliases`, `google_calendar_order_queue`, `google_calendar_order_events`, `google_calendar_locks`.

## Уведомления в Telegram

Менеджеры (активные получатели бота) получают по одному сообщению, без повторов:

- о новых будущих событиях, которые не удалось распознать (они не закрывают время);
- о возможной двойной брони — событие календаря пересекается с заказом сайта по тем же персонажам или программе;
- о событии заказа, перенесённом в Google;
- об отзыве доступа Google и о том, что календарь не читается больше 30 минут.

## Безопасность

Client Secret, refresh- и access-токены хранятся в базе зашифрованными ключом `GOOGLE_CALENDAR_TOKEN_KEY` из `.env`. Копия базы (бэкапы, локальные снимки) без этого ключа не может ни читать календарь, ни писать в него, ни отозвать доступ. Воркер по умолчанию выключен и включается только переменной `GOOGLE_CALENDAR_WORKER=1` в юните бота.

## Фоновая синхронизация

Воркер работает потоком внутри `surpriz-bot.service` (`python -m core.admin_notifications`) — отдельный сервис не нужен. Каждые 10 секунд он выгружает заказы из очереди, раз в N минут (настройка, по умолчанию 5) перечитывает события календаря на 6 месяцев вперёд. Все обращения к Google (фоновый цикл, «Синхронизировать сейчас», перечитывание после действий в админке) идут под одним lease в `google_calendar_locks`: он продлевается, пока цикл работает, и освобождается в конце, поэтому циклы никогда не пересекаются.

- Отдельный запуск: `python -m core.google_calendar`.
- Поток включается только явно: `GOOGLE_CALENDAR_WORKER=1` (в проде — в `surpriz-bot.service`). Без подключения он простаивает и не пишет в базу.
- Кнопка «Синхронизировать сейчас» в админке выполняет цикл сразу.

Выгрузка идемпотентна: у события детерминированный id (`srp<соль><id заказа>g<поколение>`), повтор после потерянного ответа превращается в обновление, дубликатов не будет. Неизменённый заказ повторно не записывается (хэш содержимого). Прошедшие заказы в календарь не добавляются. Если импорт перестал работать, последние прочитанные события продолжают закрывать время — ошибка видна в админке.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET` | данные OAuth-клиента (если не заданы в админке) |
| `GOOGLE_OAUTH_REDIRECT_URI` | явный redirect URI; по умолчанию `ADMIN_PORTAL_BASE` + `/api/admin/google-calendar/callback` |
| `GOOGLE_CALENDAR_TOKEN_KEY` | ключ Fernet для шифрования данных Google в базе; без него подключение недоступно |
| `GOOGLE_CALENDAR_WORKER` | `1` — запускать поток синхронизации в этом процессе (по умолчанию выключен) |
